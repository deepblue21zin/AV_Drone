1. 현재 파이프라인

Sensor Input

/drone1/scan publish

Perception

nearest obstacle metric 생성

Planning

gap 후보를 찾고 /drone1/autonomy/cmd_vel 생성

Safety

timeout 또는 이상 상태면 safe cmd를 0으로 만듦

Control

phase를 유지하며 MAVROS setpoint로 전달

Planner 핵심값

  • gap_search_half_angle_deg = 100
  • gap_bubble_radius = 1.15
  • gap_min_clearance = 1.60

Motion 핵심값

  • cruise_speed = 0.75
  • max_speed = 0.90
  • max_reverse_speed = 0.35

Safety 핵심값

  • pose_timeout_sec = 1.0
  • scan_timeout_sec = 0.5
  • planner_cmd_timeout_sec = 0.5

2. 운영자가 바로 쓰는 명령

기동

docker compose up -d --force-recreate sim ros
docker compose logs -f sim
# Startup script returned successfully

autonomy launch

docker compose exec ros bash
source /opt/ros/humble/setup.bash
cd /workspace/AV_Drone
source install/setup.bash
ros2 launch drone_bringup single_drone_autonomy.launch.py

핵심 topic 확인

ros2 topic echo /drone1/scan --once
ros2 topic echo /mavros/local_position/pose --once
ros2 topic echo /drone1/mission/phase --once
ros2 topic echo /drone1/mission/goal_reached --once

ros_states

ros2 launch ros_states ros_states.launch.py \
  drone_name:=drone1 \
  mavros_namespace:=/mavros \
  artifacts_root:=/workspace/AV_Drone/artifacts \
  port:=5050 \
  open_browser:=false

4. report 폴더 보고서 평가

docs/report/2026-03-31.html은 운영자가 지금 무슨 일이 일어났는지 이해하는 데는 꽤 좋다. 다만 현업의 실험 관리 체계로 보면 몇 가지가 더 필요하다.

하
잘한 점
  • 최종 phase와 goal reached를 즉시 확인할 수 있다.
  • Mission Health와 Watch Topics가 같은 페이지에 있어 triage 속도가 빠르다.
  • 중간 과정의 health 변동까지 timeline으로 드러난다.
아쉬운 점
  • error 구간의 대표 원인을 자동 요약하지 않는다.
  • artifact와 report의 run linkage가 더 강하게 보이지 않는다.
  • 이전 run 또는 baseline과 비교하는 장표가 없다.
바로 추천하는 개선
  • 상단에 git_commit, planner_version, run_id 노출
  • top safety reason 3개 요약
  • summary.json, metadata.json, events.log 링크
