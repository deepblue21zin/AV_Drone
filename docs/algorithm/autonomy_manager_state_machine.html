비행 제어 래퍼

autonomy_manager_state_machine

이 로직은 PX4 offboard operation 주변의 mission phase controller입니다. obstacle-free XY motion 자체를 고르지는 않고, 언제 setpoint를 stream할지, 언제 offboard mode와 arm을 요청할지, 언제 takeoff하고 plan을 따라가며 goal hover에 들어갈지를 결정합니다.

드론이 왜 차분해 보이는지, 왜 머뭇거리는지, 왜 특정 phase에 머무르는지 이해하려면 가장 먼저 봐야 하는 제어 페이지입니다.

주요 입력

  • MAVROS vehicle interface를 통한 vehicle state와 pose
  • /drone1/safety/cmd_vel에서 오는 safe XY command
  • /drone1/mission/goal_reached에서 오는 goal reached flag

주요 출력

  • PX4로 보내는 velocity setpoint
  • /drone1/mission/phase로 발행되는 mission phase heartbeat
  • MAVROS를 통한 mode/arm service request

Phase 순서

Phase 의미
WAIT_STREAM OFFBOARD를 안전하게 요청할 수 있을 때까지 zero setpoint를 미리 스트리밍합니다.
OFFBOARD_ARM OFFBOARD mode를 요청한 뒤, arming을 요청합니다.
TAKEOFF 수직 제어기로 설정된 takeoff altitude까지 상승합니다.
HOVER_AFTER_TAKEOFF lateral plan 추종을 시작하기 전에 잠시 정지해 안정화합니다.
FOLLOW_PLAN goal에 도달할 때까지 safe XY command와 altitude hold를 합쳐 사용합니다.
HOVER_AT_GOAL lateral motion을 멈추고 goal altitude를 유지합니다.

고도 제어 로직

planner가 XY behavior를 맡고 있을 때도 Z control은 state machine이 담당합니다. follow mode에서는 safe planner command가 lateral velocity를 제공하고, manager가 altitude error로부터 vz를 계산합니다.

복구 로직

mission 시작 후 OFFBOARD mode나 arming이 풀리면 node는 다시 OFFBOARD_ARM으로 들어갑니다. 그래서 어떤 run은 일시적으로 불안정해 보여도 복구 후 성공적으로 끝날 수 있습니다.

로그에서 어떻게 보이는가

  • PHASE => ... 는 phase transition을 의미합니다.
  • Requesting OFFBOARD mode 는 mode handover가 진행 중일 때 보입니다.
  • Requesting arm 은 arming을 기다리는 동안 보입니다.
  • Takeoff reference locked: ... 는 어떤 altitude reference를 잡았는지 설명합니다.
  • Already airborne at z=... 는 takeoff를 건너뛴 경로를 설명합니다.

왜 report 해석에 중요한가

최종 상태가 HOVER_AT_GOAL이라는 것은 mission이 끝났다는 뜻일 뿐, 그 과정이 깔끔했는지까지 알려주진 않습니다. 흔들림을 이해하려면 phase transition, safety event, command dropout, 그리고 report의 stability summary를 함께 읽어야 합니다.
