알고리즘 문서

현재 활성 알고리즘 맵

이 폴더는 현재 AV Drone 런타임에서 실제로 동작하는 알고리즘 경로를 설명합니다. 가장 중요한 점은 지금 실행 중인 planner가 MPPI가 아니라 local_planner_follow_the_gap라는 것입니다.

런타임 순서: 원시 LiDAR scan -> nearest obstacle metric 및 gap planner -> safety gate -> PX4 offboard phase state machine.

지금 실제로 활성인 알고리즘

플래너

local_planner_follow_the_gap

scan 안의 free gap을 찾고, goal 방향과 비교해 점수를 매긴 뒤, body-to-world velocity command를 내보내는 반응형 local planner입니다.

인지

nearest_obstacle_extraction

모니터링과 리포팅을 위해 가장 가까운 valid obstacle distance만 뽑아내는 최소 LiDAR 요약 단계입니다.

안전

safety_timeout_guard

timeout과 optional obstacle emergency stop으로 stale하거나 unsafe한 planner 출력을 차단하는 guard layer입니다.

제어

autonomy_manager_state_machine

setpoint stream, arm, takeoff, plan 추종, goal hover를 단계적으로 관리하는 phase 기반 비행 제어 래퍼입니다.

런타임 흐름

  1. LiDAR 노드가 LaserScan을 받고 nearest-obstacle metric을 발행합니다.
  2. local planner가 pose와 scan을 읽고 gap 기반 velocity command를 선택합니다.
  3. safety monitor가 pose, scan, planner command의 freshness를 확인한 뒤 전달 여부를 결정합니다.
  4. autonomy manager가 safe XY motion에 altitude hold와 PX4 offboard phase logic을 합칩니다.

로그 읽는 법

  • PHASE => ... 는 autonomy manager에서 나오며 mission state transition을 뜻합니다.
  • Safety state changed: ... 는 safety guard에서 나오며 command가 왜 차단됐는지 설명합니다.
  • planner 자체는 조용한 편이라, 실제 동작은 command, phase, report artifact를 함께 보고 해석하는 경우가 많습니다.
  • 이제 report에는 stability, root-cause summary, artifact linkage가 함께 들어갑니다.

여기서 다루지 않는 것

저장소에는 여전히 src/mppi/ 아래에 MPPI 코드가 남아 있지만, 현재 active launch path는 planner를 local_planner_follow_the_gap로 식별합니다. 그래서 이 폴더는 현재 런타임 알고리즘을 우선 문서화하고, MPPI는 현재 mission planner가 아닌 참고용 코드로 취급합니다.
