인지 유틸리티

nearest_obstacle_extraction

이 node는 최소한의 perception reduction 단계입니다. obstacle을 분류하거나 semantic scene을 만들지는 않고, 현재 LiDAR scan을 하나의 scalar 값, 즉 가장 가까운 valid obstacle distance로 압축합니다.

현재 stack에서는 완전한 autonomy algorithm이라기보다 monitoring과 reporting을 위한 signal에 가깝습니다.

입력과 출력

  • 입력 topic: /drone1/scan
  • 출력 topic: /drone1/perception/nearest_obstacle_distance
  • 출력 타입: std_msgs/Float32

이것이 아닌 것

  • tracker가 아닙니다.
  • clustering pipeline이 아닙니다.
  • main gap logic용 planner input transformer가 아닙니다.
  • world model이 아닙니다.

알고리즘

  1. raw LaserScan을 subscribe합니다.
  2. non-finite range를 제거합니다.
  3. range_min보다 작은 sample을 제거합니다.
  4. 남은 range 중 최소값을 구합니다.
  5. 그 최소값을 nearest obstacle distance로 publish합니다.

valid range가 하나도 없으면 node는 inf를 publish합니다. 로직은 의도적으로 단순하고 deterministic합니다.

어떻게 활용되는가

local planner와 safety monitor는 둘 다 raw scan을 직접 읽기 때문에, 이 topic은 observability signal로 이해하는 것이 맞습니다. 대시보드, metrics, alert threshold, 사람이 읽는 report에 특히 유용합니다.

로그에서 어떻게 보이는가

  • 시작 시 Perception scaffold ready: ... 한 줄을 출력합니다.
  • 값 자체는 주로 topic, metrics capture, downstream report에서 확인합니다.
  • 값이 계속 inf라면 먼저 scan validity와 sensor freshness를 확인하는 것이 맞습니다.

운영상 해석 포인트

이 node가 유용한 이유는 단일 nearest-distance 값이 시간축 그래프로 보기 쉽기 때문입니다. 실제로는 mission이 평온했는지, 공간이 빡빡했는지, emergency stop threshold 근처를 반복적으로 스쳤는지를 가장 빨리 보여주는 지표 중 하나입니다.

이 metric이 active stack 전체에서 어떤 위치인지 보려면 algorithm index로 돌아가면 됩니다.
