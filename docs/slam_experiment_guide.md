# 실험 해석 가이드

AV_Drone의 **현재 구현과 저장된 실험**을 읽기 위한 README입니다.
여기서 B0·B1·N·R·O는 드론 이름이나 센서 이름이 아니라 **같은 비행 기록을 처리하는 비교 조건**입니다.

처음에는 **1번 조건표 → 2번 B0/B1 차이 → 5번 그래프 읽기** 순서로 읽으면 됩니다.

## 1. B0 · B1 · GT · O · R · N 한눈에 보기

| 이름 | 쉽게 말하면 | 위치·보정 정보를 어디서 얻나? | GT를 보정 과정에 쓰나? |
|---|---|---|---|
| **B0** | 드론끼리 보정하지 않은 원래 SLAM | 외부 odometry + 각 드론 SLAM의 `map→odom` 변환 | 드론 간 제약 생성에는 사용하지 않음 |
| **B1** | 외부 위치 추정만으로 만든 비교 기준 | 초기 좌표 정렬 + MAVROS/PX4 외부 odometry. SLAM의 `map→odom` 보정은 적용하지 않음 | 드론 간 제약 생성에는 사용하지 않음 |
| **GT** | 평가할 때 비교하는 정답 | Gazebo가 제공하는 실제 시뮬레이션 pose | GT 자체는 평가 기준. Oracle 조건에서는 제약 생성에도 사용 |
| **O-single** | 정답 기반 상대 pose 제약 1개로 보정 | GT로 상대 pose를 만들고 pose graph에 추가 | **사용함** |
| **O-periodic** | 정답 기반 상대 pose 제약 여러 개로 보정 | 진행 구간마다 GT 기반 상대 pose 제약 추가 | **사용함** |
| **R-single / R-periodic** | 장소 선택은 정답의 도움을 받고, 맞추는 값은 LiDAR로 계산한 과거 실험 | GT 기반 진행거리로 비교할 submap pair를 고른 뒤 LiDAR 정합 | **pair 선택 등에 사용함**. 상대 pose 측정값 자체는 LiDAR로 계산 |
| **N-single** | GT 없이 후보를 찾고 LiDAR 제약 1개로 보정 | LiDAR 형상 + raw-SLAM 위치 prior → 정합 → 이웃 일관성 검사 → 제약 1개 | **추론에는 사용하지 않음. 평가에만 사용** |
| **N-prior** | 초기 정렬 효과만 분리한 대조군 | raw SLAM pose graph에 알려진 시작 pose prior만 적용. 드론 간 제약은 0개 | 평가에만 사용 |
| **N-single-A / N-single-B** | 앞쪽 구간만 / 뒤쪽 구간만 보정 | 서로 떨어진 LiDAR 검증 구간 중 한 곳의 대표 제약 1개 | 평가에만 사용 |
| **N-double** | 두 구간의 대표 제약을 함께 적용 | 같은 bag, 같은 초기 pose·가중치에서 A와 B 제약을 모두 사용 | 평가에만 사용 |

공통 주의사항:

- 현재 비교에서는 **초기 드론 간 좌표계 정렬을 알고 있다**고 가정합니다. 초기 위치·방향까지 모두 모르는 문제를 해결한 것은 아닙니다.
- 과거 분석은 GT를 동기화·진행거리 표본화에도 사용했습니다. B0/B1이라는 이름만으로 전체 분석 파이프라인이 GT-free라고 판단하면 안 됩니다.
- 최신 N-single 경로는 GT 없이 데이터 선택·후보 검색·정합·최적화를 끝내고, 결과를 저장한 다음 GT를 읽어 평가합니다.
- `single`은 최종 드론 간 **제약 1개**라는 뜻입니다. scan 1장, 통신 패킷 1개, 실제 만남 1회를 뜻하지 않습니다.
- `periodic`의 개수는 설정과 비행 길이에 따라 달라집니다. 항상 7개라는 뜻은 아닙니다.
- 2구간 실험에서는 **조건 성립·채택 제약·실제 적용·최적화 성공**을 먼저 확인합니다. B 구간이 검증되지 않으면 N-single-B는 유효한 비교군이 아니며, N-double이라는 이름만으로 2개 적용을 뜻하지 않습니다.
- A/B는 raw-SLAM 진행 순서에 따른 독립 검증 구간입니다. GT나 사전에 정한 경로 구간을 정합 정답으로 넣지 않습니다.

## 2. B0와 B1은 정확히 무엇이 다른가?

**B0는 B1이 사용하는 외부 odometry에 각 드론의 SLAM 위치 보정을 반영한 결과입니다.**
따라서 B0를 “SLAM 자체가 없는 조건”으로 이해하면 안 됩니다.
B0에 없는 것은 **다른 드론의 관측을 이용한 추가 보정**입니다.

| 구성 | B1 | B0 | N-single |
|---|---|---|---|
| 초기 좌표 정렬 | 사용 | 사용 | 사용 |
| 외부 odometry | 사용 | 사용 | 사용 |
| 각 드론의 SLAM `map→odom` 보정 | 미적용 | 적용 | 적용 |
| 다른 드론과의 LiDAR 제약 | 없음 | 없음 | 1개 적용 |

지도 비교에서는 같은 기록의 LiDAR scan을 **각 조건의 pose에 맞춰 다시 배치**합니다.
따라서 센서를 바꾼 비교가 아니라, 주로 **scan을 어느 위치·방향에 놓는가**의 비교입니다.

### 외부 odometry와 SLAM pose

- **외부 odometry**: MAVROS를 통해 받은 PX4의 위치·방향 추정입니다. 여기서 “외부”는 SLAM 알고리즘 바깥에서 온다는 뜻이지, 외부 서버나 GT라는 뜻이 아닙니다.
- **SLAM pose**: 외부 odometry에 LiDAR 정합으로 얻은 `map→odom` 변환을 반영한 추정입니다. 지도와 맞추면서 위치·방향이 달라질 수 있습니다.
- **known_pose**: 이 프로젝트의 해당 지도 생성·융합 설정에서는 초기 정렬과 외부 odometry를 사용하는 이름입니다. `GT pose`와 같은 말이 아닙니다.

### 왜 B1이 B0보다 좋을 수도 있나?

SLAM을 추가했다고 무조건 정확해지는 것은 아닙니다. 시뮬레이션의 외부 odometry가 충분히 정확한데
LiDAR 정합이 반복되는 원통 형상 등으로 잘못된 보정을 누적하면 B0가 더 나빠질 수 있습니다.
이는 가능한 설명이며, 특정 실행의 원인을 확정하려면 odometry·TF·정합 기록을 함께 점검해야 합니다.
B0/B1의 숫자는 성능 순위나 개발 순서를 뜻하지 않습니다.

## 3. pose · 상대 pose · submap · 제약

| 용어 | 이 프로젝트에서의 의미 |
|---|---|
| pose | 위치와 방향. 현재 오프라인 보정은 평면의 `(x, y, yaw)`를 다룸 |
| yaw | 위에서 내려다봤을 때 드론이 바라보는 방향각 |
| 상대 pose | 한 드론의 관측 좌표계에서 다른 드론의 관측 좌표계가 어디에 있고 어느 방향인가 |
| keyframe | 전체 관측 중 이동·회전 기준으로 선택한 대표 pose |
| submap | 가까운 구간에서 얻은 여러 LiDAR 관측을 묶은 작은 지도 |
| registration / 정합 | 두 submap을 이동·회전시켜 겹치는 형상이 맞도록 상대 변환을 추정하는 과정 |
| pair | 서로 비교하는 두 submap의 쌍. 후보라고 모두 같은 장소인 것은 아님 |
| factor / 제약 | “이 두 pose의 상대 관계는 이 정도다”라는 측정과 불확실성. 최적화에 추가하는 연결 |
| pose graph 최적화 | 기존 경로 연결과 새 제약이 함께 잘 맞도록 여러 pose를 조정하는 계산 |
| drift / 드리프트 | 이동하면서 누적되는 위치·방향 추정 오차 |

새 제약은 정답 위치로 순간이동시키는 명령이 아닙니다. 기존 연결과 제약의 가중치에 따라
여러 pose에 보정이 나뉘어 적용됩니다. 그 pose를 사용해 LiDAR scan을 다시 배치한 것이 보정 지도입니다.

## 4. Oracle과 “한 번 만남”에서 주의할 점

**Oracle은 현실에서는 알기 어려운 정보를 알고 있다고 가정한 비교 조건**입니다.
여기서는 GT에서 상대 pose를 계산해 제약으로 넣습니다. 구현 설정에 따라 그 측정에 잡음도 더합니다.
전체 궤적을 GT로 덮어쓰는 것은 아니므로 Oracle 결과도 오차가 0일 필요는 없습니다.
모든 지표에서 반드시 가장 좋다는 보장도 아닙니다.

O-single/O-periodic은 실제 두 드론의 관측이 겹치는 횟수와 무관하게 GT로 제약을 만들 수 있습니다.
그래서 “상대 정보를 알 수 있다면 보정 효과가 있는가?”를 확인하는 용도입니다.

기존 전체맵 N-single 실험은 다음과 같습니다.

1. 경유점을 미리 정해 중간에 주 공통 관측 구간이 생기도록 비행했습니다.
2. 동시에 만나 통신하지 않고, 서로 다른 시간에 같은 장애물 구역을 관측했습니다.
3. 비행 후 두 드론의 기록을 함께 읽어 LiDAR 상대 pose를 추정했습니다.
4. 여러 후보와 이웃 지지를 검사한 뒤 대표 제약 1개만 적용했습니다.

따라서 **“공통 관측을 이용한 오프라인 제약 1개 보정”**이 정확한 표현입니다.
실제 통신 횟수·통신량·실시간 재회 경로를 구현하거나 평가한 결과는 아닙니다.
주 공통 구간 외의 약한 중첩도 있으므로 엄밀히 “겹침이 정확히 한 번뿐”이라고 단정하지 않습니다.

### 2구간 비교는 무엇이 다른가?

고정 경로에 두 공간적 공통 관측 구간을 의도하고, 기록 후 LiDAR로 각각 검증합니다.
주변 독립 anchor pair가 서로 지지하는 후보들을 묶어 구간당 대표 1개만 선택합니다.
두 대표는 양쪽 드론의 raw-SLAM 누적거리로 각각 30m 이상, 공간적으로 각각 25m 이상 떨어져야 합니다.
실제 겹침이 있다고 해서 정합이 성공하거나, 유효 구간이 정확히 두 개라는 보장은 없습니다.

같은 기록의 **N-single-A vs N-double**이 두 번째 제약을 추가한 비교입니다.
**N-single-B vs N-double**도 함께 봐야 “후반 제약 하나만으로 충분했는가?”를 확인할 수 있습니다.
이전 1구간 비행과 새 2구간 비행은 경로와 센서 입력이 달라 횟수 효과만의 비교로 쓰면 안 됩니다.
**N-prior**는 시작 prior를 적용하는 것만으로 달라지는 효과를 분리합니다. N 계열끼리는 동일한 prior와 가중치를 씁니다.
상대 위치뿐 아니라 각 드론의 절대 오차·지도 Chamfer도 함께 비교하세요.

**“1회·2회 비교 성립”과 “보정 평가 통과”는 별개입니다.**
앞 표시는 A=1개, B=1개, A+B=2개가 각각 최적화에 실제 적용됐다는 뜻입니다.
뒤 표시는 선택한 상대 pose가 GT 사후 평가에서 맞는지, 위치·yaw·지도 지표가 개선됐는지를 뜻합니다.
따라서 두 제약을 정상 적용했어도 일부 오차가 커져 종합 평가는 미달일 수 있습니다.
엄격한 분석 실행(`--require-complete-ablation`)은 실제 1/1/2 적용이 안 되면 지도·GT 평가 전 중단합니다.

## 5. 그래프와 지표 읽는 방법

| 화면·지표 | 무엇을 보나? | 좋은 방향 / 주의점 |
|---|---|---|
| Trajectories / 이동 궤적 | 각 조건의 경로가 GT 경로와 얼마나 다른가 | GT에 가까울수록 좋음. 두 드론을 각각 확인 |
| 절대 위치 오차 / ATE | 각 드론의 추정 위치와 GT 위치 차이 | 작을수록 좋음. 현재 평가에서는 초기 정렬된 좌표에서 비교하며 전체 궤적을 GT에 사후 best-fit 정렬하지 않음 |
| Relative Drift / 상대 위치 오차 | 두 드론 사이의 추정 상대 변환과 GT 상대 변환의 차이 | 작을수록 좋음. 실제 드론 간 거리가 가까워졌다는 뜻은 아님 |
| yaw error | 추정 방향과 정답 방향의 차이 | ±180° 범위로 감싼 차이의 절댓값. 작을수록 좋음 |
| RMSE | 여러 표본의 오차 제곱 평균에 제곱근을 취한 값 | 큰 오차의 영향을 더 받음. 작을수록 좋음 |
| 종단 오차 / endpoint | 끝부분 pose의 오차 | 전체 구간 평균과 다름. RMSE와 함께 확인 |
| RPE | 일정 이동 구간에서 추정한 상대 이동과 GT 상대 이동의 차이 | 국소적인 이동 오차. 드론 두 대 사이의 상대 오차와는 다른 지표 |
| 지도 Chamfer [m] | 추정 지도와 기준 지도 점유셀의 최근접 거리를 양방향으로 평균 | 작을수록 좋음. 같은 장애물의 ID를 찾아 비교하는 지표는 아님 |
| 지도 F1 | 점유셀의 precision·recall을 함께 평가한 값 | 1에 가까울수록 좋음. 격자 단위 일치이므로 작은 이동에도 민감 |
| coverage / unknown | 관측한 영역 / 아직 모르는 영역 | 많이 관측했다고 위치가 정확한 것은 아님 |

### 상대 오차와 절대 오차는 왜 따로 보나?

예를 들어 두 드론의 추정 위치가 **둘 다 동쪽으로 3m** 밀리면, 서로의 상대 위치는 맞아도
절대 위치는 둘 다 틀릴 수 있습니다. 그래서 상대 오차 감소만으로 지도 정확도 개선을 선언하면 안 됩니다.

실제로 2026-09-11 전체맵 기록의 B0 → N-single은 다음과 같았습니다.

| 항목 | B0 | N-single | 해석 |
|---|---:|---:|---|
| 종단 상대 위치 오차 | 7.935m | 1.245m | 개선 |
| 상대 yaw RMSE | 3.343° | 0.729° | 개선 |
| 지도 Chamfer | 1.632m | 2.110m | 악화 |

이 표는 해당 실행의 예시입니다. 다른 실행의 결과는 선택한 실험의 지표를 확인하세요.

### yaw 그래프에서 +179°와 −179°는?

두 방향의 차이는 358°가 아니라 **짧은 방향으로 2°**입니다.
또한 드론이 실제로 회전한 각도와 yaw 오차는 다릅니다. 추정도 정답도 함께 회전하면 yaw 오차는 작을 수 있습니다.
`상대 yaw`는 두 드론 사이 방향 관계의 오차이고, `절대 yaw`는 각 드론 방향의 GT 대비 오차입니다.

### 가로축과 종단 값이 다르게 보일 때

- 최신 GT 평가 전용 N-single 분석의 상대 오차 곡선은 **공통 raw-SLAM 누적거리**를 기준으로 표본화합니다.
- 최신 종단 상대 오차는 **각 드론의 마지막 GT 평가 가능 keyframe**을 비교합니다. 같은 시각의 pose라는 뜻은 아닙니다.
- 경로 길이가 다르면 상대 오차 곡선의 마지막 표본과 종단 값이 다를 수 있습니다.
- 과거 Oracle/R 분석은 GT 기반 진행거리와 마지막 공통 진행거리 표본을 사용했습니다. 실행 간 숫자를 비교하기 전에 축과 종단 정의를 확인하세요.
- 전진 목표 142m, 실제 누적 비행거리, raw-SLAM 누적거리는 서로 다른 양입니다.

### 지도 그림 색과 평가 범위

`전체 지도 오차` 비교 그림에서:

- **초록**: GT-reference에는 점유지만 추정 지도에는 점유가 아닌 셀.
- **빨강**: 추정 지도에는 점유지만 GT-reference에는 점유가 아닌 셀.
- **검정**: 두 지도에서 점유가 일치하는 셀.
- **회색**: 두 지도 모두 미관측인 셀.

궤적 그래프나 다른 지도 탭의 색은 별도 범례를 따릅니다.
GT-reference도 **같은 LiDAR 관측을 GT pose로 투영한 지도**이지 월드 전체의 완벽한 설계도는 아닙니다.
현재 지도 F1·Chamfer는 두 지도에서 공통으로 관측된 영역에서 계산하므로 coverage도 함께 확인해야 합니다.

## 6. 실제 Streamlit 확인 순서

1. 왼쪽 **실험 보기**에서 이름으로 실험을 선택합니다.
2. 제목 아래 **실험 목적**과 GT 사용 범위를 읽습니다.
3. **실험 요약**에서 같은 bag의 B0/B1/보정 조건을 비교합니다. 위치·yaw·지도를 모두 봅니다.
4. **LiDAR 상세**에서 채택 수와 실제 적용 수·최적화 성공 여부를 확인하고, **Registration**의 `accepted=true` pair를 봅니다. 채택됐어도 최적화 실패 시 적용되지 않을 수 있습니다.
5. **Drift & Trajectory / Maps**에서 보정이 어느 구간에 영향을 주었는지 확인합니다.
6. **보고서·파일**에서 한계와 원본 ID를 확인하고 CSV·그림을 내려받습니다.

**기록 정상 완료**는 비행·저장 상태이고, **종합 개선 판정**은 보정 성능의 평가입니다.
`FAIL`이라고 분석 코드가 실패했거나 데이터가 쓸모없다는 뜻은 아닙니다.
정합을 하나도 채택하지 못하면 N-single이 B0를 유지할 수도 있으므로 먼저 제약 개수를 확인하세요.

비행 중 저장된 `known_pose` 지도와 비행 후 만든 `N-single` 지도도 구분해야 합니다.
전자는 외부 odometry 기반 지도, 후자는 LiDAR 드론 간 제약을 적용한 오프라인 보정 지도입니다.

## 7. 발표할 때 피해야 할 표현

| 오해하기 쉬운 표현 | 더 정확한 표현 |
|---|---|
| B0는 SLAM을 안 했다 | B0는 개별 SLAM을 사용하지만 드론 간 보정은 안 했다 |
| B1은 GT다 | B1은 초기 정렬과 외부 MAVROS/PX4 odometry를 쓴 비교군이다 |
| 한 번 만나서 통신했다 | 공통 관측 기록에서 대표 제약 1개를 만들어 비행 후 보정했다 |
| LiDAR로 계산했으니 전부 GT-free다 | 후보 선택·시간 처리·초기 정렬·측정·최적화·평가에서 GT 역할을 각각 확인했다 |
| 상대 오차가 줄었으니 지도도 좋아졌다 | 상대 오차와 절대 궤적·지도 오차를 별도로 평가했다 |
| 전체맵을 100% 관측했다 | 맵의 전체 길이를 활용했지만 가림과 미관측 영역이 남았다 |
| 다른 run보다 숫자가 작으니 알고리즘이 우수하다 | 경로·입력 bag·설정·평가 정의가 같은 비교인지 먼저 확인한다 |

현재 결과는 초기 좌표 정렬을 아는 고정 경로·오프라인 보정 실험입니다.
실시간 통신 효율, 자율 재회 계획, 미지 초기 위치 전역 정합, 여러 반복 실험에서의 일반화는 별도 과제입니다.
