Follow-the-Gap의 실제 순서

  • scan을 ±100° 범위로 자른다.
  • gap_bubble_radius = 1.15로 obstacle 주변을 막는다.
  • gap_min_clearance = 1.60, 최소 8포인트인 gap만 후보로 본다.
  • goal alignment + clearance + width 점수로 best gap을 고른다.
  • gap이 없거나 너무 좁으면 reverse + lateral escape로 빠진다.

이 의미가 중요한 이유

  • 현재 planner는 global map replanning이 아니다.
  • corridor처럼 좁은 환경에서 통과 틈을 찾는 reactive planner다.
  • 멀티드론 협업, task reallocation, MPPI return은 다음 단계다.

3. report 폴더 보고서 평가

docs/report/2026-03-31.html은 운영 가독성은 높다. 실제로 최종 HOVER_AT_GOAL, goal reached, obstacle/speed timeline, Mission Health를 한 화면에 보여 준다. 다만 현업 기준으로는 아직 “설명용 report”에 가깝고 “의사결정용 audit report”는 아니다.

좋음
  • session 상태와 watch topic을 빨리 읽을 수 있다.
  • timeline으로 과정 중 health 흔들림까지 보인다.
  • 초심자 인수인계 자료로 강하다.
보강 필요
  • error 구간의 대표 원인 요약이 없다.
  • run id, git commit, config snapshot 연결이 약하다.
  • 이전 run과 비교가 없다.
추천 개선
  • top safety reason 3개 자동 요약
  • summary.json / metadata.json 바로가기
  • baseline 간 비교 카드 추가
